Module 15 · 15_jev_sees_images

Jev sees images: photos, Box and long context

Released 2026-10-14 as TypeSafe's "danger zone": an image can go anywhere text can go, a box question says where something is, and a header raises the context to 262k tokens. Students send photos without a vision LLM in between and measure when that helps.

Images work on 1.13 too"Multimodal all along", but only with the header TypeSafe-Danger-Zone-Images: true. Without it: HTTP 400.
Box is 1.14 onlyIt always returns a box, even around nothing. Ask a yes/no question in the same request and let code ignore the box when it's low.
Jev still writes no textIt can say the thermostat is above 28 °C, but never "29.1". Exact numbers stay with a vision LLM or OCR, checked by code.
Module 16 · 16_local_system_one_models

Local System One models vs Jev, measured fairly

systemonemodels.org lists 25+ decision models, nine with open weights. The labs run three on the laptop with no network, then put all engines through the same 18 English and Thai tickets with the same questions and the same scoring.

Watch for this before trusting a local model on Thai Laya's multilingual checkpoint sent "burning smell near the electrical cabinet" to plumbing with 0.95 confidence. The English-only GLiNER2.5-Decide made the same mistake; its multilingual sibling got safety. Confidence alone did not catch it. Testing the language you serve did.
Extract, then decideClassic GLiNER finds every room number with offsets. Jev picks which one has the problem. In Thai, GLiNER also marked floor 3 as a room; Jev chose 1203 at 0.92.
Scoreboards measure different jobsIndependent index: Jev 60, Decide 9, Laya 4. Fastino's own suite: Decide 60.2, Jev 57.6. Laya fine-tuned on one task: 79.4 vs Jev 80.0. All true.
Confidential text stays localThe exercise's engine picker never sends confidential text to the cloud. An unsure local answer goes to a person, not to Jev.
Module 17 · 17_finetune_system_one

Fine-tune a local model, then let locked criteria decide

Module 16 ended with base Laya routing 12 of 18 tickets. Here students fine-tune Laya (full, Apple GPU) and GLiNER2.5-multi-Decide (a 5.5 MB LoRA adapter and a full fine-tune, CPU) on 456 English and Thai tickets. They write seven pass/fail criteria before training, then grade every model on 66 hand-written tickets it never saw.

GLiNER2.5-multi-Decide with a 5.5 MB LoRA adapter, held-out tickets. Broke none. Laya: 40 → 55
3.9 min
Laya fine-tune on the M4 Max's GPU. GLiNER trains on the CPU (its trainer has no Mac GPU path): 7.2 min LoRA, 6.7 min full

ten lines of keyword rules, which beat every local model before fine-tuning (40 / 66)
3 × HOLD
all fail C3: each misses water reaching a switchboard room. The gate, not the +30 points, decides
Laya's confidence broke while its accuracy improved After fine-tuning, Laya's mean confidence on validation was 0.997 while it was right 89 % of the time. Its own temperature fit "came back unchanged at 1.0", because the calibration slice came from training situations it already got 100 % right. A cut fitted on validation still let through 15 % errors on held-out tickets. Fine-tuned confidence needs checking on data the model has not seen.
Mac first, Spark when it growsAbout 300M-parameter encoders need roughly 5 GB to fine-tune. A Mac does 456 tickets in minutes. The Spark earns its place above about 5k tickets, for repeated runs, or when GLiNER needs a CUDA GPU.
Lock the criteria firstcriteria.json is hashed before training. The gate refuses to grade if it changed or if a checkpoint is older than the lock.
A HOLD names the next stepWrite training situations for the missed category, retrain, and then write fresh held-out tickets: once you've studied the old ones, they are spent.
